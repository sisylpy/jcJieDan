# 京京接单 · 平台客户订单接口说明（配送商端）

> **读者**：`jcJieDan` 配送商小程序前台开发（Cursor 可直接 `@` 本文件联调）。  
> **维护**：Java 后台 `PlatformDistributerController`、`NxDepartmentOrdersController` 及关联 Service。  
> **Base URL**：与项目现有 NX 后端一致，例如 `http://localhost:8080/nongxinle_war_exploded/`

---

## 1. 三类客户，三套入口（必读）

配送商首页「今日订货客户」存在 **三种业务来源**，**不可混用**：

| 类型 | 业务含义 | 列表数据来源 | 点进客户后的订单页 |
|------|----------|--------------|-------------------|
| **平台客户** | 京采市场饭店经平台下单、已分配给本配送商 | **`POST api/platform/distributer/customers/today`**（新） | `orderPage`（GB 平台：`depFatherId=-1` + `routeGbDepFatherId`；NX 平台：`routeDepFatherId` + `gbDepFatherId=-1`） |
| **我的客户** | 配送商自有 nx_department 老客户 | `GET/POST api/nxdepartmentorders/disGetTodayOrderCustomer/{disId}` 的 `deps.nxDep` | 同上 `orderPage` |
| **GB 饭店客户** | G 地 gb_department 体系饭馆 | 同上接口的 `deps.gbDisArrApp` | **`orderPageGb`**（GB 链路，`toDepOrdersGb`） |

**改造要点（相对旧版）：**

- `disGetTodayOrderCustomer` **不再返回**平台客户（`deps.platformDep` 恒为空数组）。
- 平台客户 **单独** 调 `api/platform/distributer/customers/today`，在 WXML 中单独区块展示，**不要**与 `gbDisArrApp`、自有 `nxDep` 合并成 `customerSections`。

## 2. 平台客户列表（新接口）

### 2.1 请求

`POST api/platform/distributer/customers/today`

```json
{
  "disId": 56
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `disId` | Integer | 是 | 当前登录配送商 `nx_distributer_id` |

### 2.2 响应

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "customerCount": 2,
    "unDoTotal": 3,
    "customers": [
      {
        "dep": {
          "nxDepartmentId": 1201,
          "nxDepartmentAttrName": "三店",
          "nxDepartmentSettleType": 1,
          "nxDepartmentSubAmount": 0,
          "isPlatformCustomer": 1,
          "orderSource": "PLATFORM",
          "platformLabel": "平台客户"
        },
        "totalCount": 5,
        "finishCount": 2,
        "hasPrice": 5,
        "hasWeight": 1,
        "unDo": 1,
        "twoSubtotal": "128.5",
        "isPlatformCustomer": 1,
        "orderSource": "PLATFORM",
        "platformLabel": "平台客户",
        "platformSort": 0,
        "customerSource": "GB",
        "displayName": "测试饭店",
        "routeDepFatherId": -1,
        "routeGbDepFatherId": 57,
        "gbDepartmentId": 57,
        "gbDepartmentName": "测试饭店",
        "marketId": 1
      }
    ]
  }
}
```

| 字段 | 说明 |
|------|------|
| `customerSource` | `GB`=京采市场饭店下单（主流）；`NX`=旧 nx_department 平台客户 |
| `displayName` | 列表展示名，优先饭店名 |
| `routeDepFatherId` / `routeGbDepFatherId` | 跳转 `orderPage` 时传入（见 §4.1） |
| `customers[].dep` | 展示用部门对象；**跳转参数以 route* 为准** |
| `gbDepartmentId` / `gbDepartmentName` | 京采市场饭店（与 `gbDisArrApp` 的 G 地 GB 客户不是同一套） |
| `totalCount` / `hasWeight` / `unDo` 等 | 统计口径与旧平台项一致 |
| `customerCount` | 平台客户家数 |
| `unDoTotal` | 所有平台客户待处理行合计 |

> **根因说明（2026-06-20 修复）**：京采 `submitBySupplier` 产生的平台单 `nx_DO_gb_department_id > 0` 且 `nx_DO_department_father_id = -1`，旧 SQL 误加 `gb_department_id = -1` 导致列表恒为空。

### 2.3 判定规则（后端）

仅包含满足以下条件的客户：

- 存在 `nx_platform_order_assign` 且 `assign_mode=PLATFORM`、`assign_status=ASSIGNED`
- 订单 `nx_DO_distributer_id = disId`，且 `nx_DO_status >= 0`（**正式单**；购物车 `status=-1` **不可见**）
- 订单 `nx_DO_status < 3`

**Checkout 前边界（2026-06-21 购物车重构）**：

| 阶段 | 配送商端 | Electron 分配台 |
|------|----------|-----------------|
| 购物车临时行 `nx_DO_status=-1` | **不可见** | **不可见** |
| `checkoutConfirm` 后 `ASSIGNED` | **可见**（本接口 §2、§4） | 客户自选，不可取消分配 |
| `checkoutConfirm` 后 `PENDING` | **不可见** | **可见**，待平台分配 |

饭店端加购接口（`submitBySupplier` / `submitLine`）**不再**直接产生配送商可见单；必须等饭店 **checkoutConfirm** 之后。

PENDING（平台尚未分配）的单 **不会** 出现在配送商列表。

### 2.4 错误码

| code | 含义 |
|------|------|
| `0` | 成功 |
| `4002` | 参数错误（如 `disId` 为空） |

`GET/POST api/nxdepartmentorders/disGetTodayOrderCustomer/{disId}`

### 3.2 响应结构（与平台相关的变更）

```json
  "code": 0,
  "data": {
    "deps": {
      "nxDep": [ /* 仅配送商自有 nx 客户 */ ],
```

## 4. 平台客户 — 专用订单接口（勿用自有 nx 出库接口）

> **重要**：平台订单的拉单、改重量、出库完成、改价、取消出库，**全部走** `api/platform/distributer/orders/*`。  
> **不要**再调用 `phoneGetToFillDepOrders` / `updateOrderWeight` / `updateOrderPrice` / `cancelOutOrder`（那是自有 nx 客户链路）。

### 4.1 接口一览

| 用途 | 方法 | 路径 |
|------|------|------|
| 拉取平台客户订单行 | POST | `api/platform/distributer/orders/lines` |
| 仅保存出库重量（未出库） | POST | `api/platform/distributer/orders/saveWeight` |
| **出库完成**（录重量 + 完成 + READY_FOR_PICKUP） | POST | `api/platform/distributer/orders/finishOutbound` |
| 修改实际单价 | POST | `api/platform/distributer/orders/updatePrice` |
| 取消出库 | POST | `api/platform/distributer/orders/cancelOutbound` |

统一响应：`code === 0` 成功；`4002` 参数/业务校验失败。

### 4.2 拉取订单行

`POST api/platform/distributer/orders/lines`

```json
{
  "disId": 56,
  "depFatherId": -1,
  "gbDepFatherId": 57,
}
```

| 字段 | GB 平台客户 | NX 平台客户 |
|------|-------------|-------------|
| `depFatherId` | **-1** | `routeDepFatherId` |
| `gbDepFatherId` | **`routeGbDepFatherId`** | -1 |

返回 `data`: `NxDepartmentOrdersSimpleDTO[]`，仅含 **checkout 后、`nx_DO_status >= 0` 且 assign=ASSIGNED** 的平台单，带 `isPlatformOrder=1`、`expectPrice` 等。  
购物车临时行（`status=-1`）**不会**出现在本接口。

### 4.3 保存重量（未出库）

`POST api/platform/distributer/orders/saveWeight`

```json
{ "disId": 56, "orderId": 200210, "weight": "3.5" }
```

- 写 `nx_do_weight`、重算小计/差价
- **同步**关联 `gb_department_orders`：重量、小计、`gb_do_buy_status` / `gb_do_status`（与 `updateOrderWeightGb` 一致）
- **不会**标记出库完成

### 4.4 出库完成（核心）

`POST api/platform/distributer/orders/finishOutbound`

```json
{ "disId": 56, "orderId": 200210, "weight": "3.5" }
```

- 写重量 + `purchase_status` 出库完成 + `status` 已完成
- **同步** GB 订单重量/小计/状态，并更新 GB 采购商品汇总重量（与 `giveOrderWeight*` 出库链路一致）
- 同步 `nx_platform_order_fulfillment` → **`READY_FOR_PICKUP`**

### 4.5 修改单价

`POST api/platform/distributer/orders/updatePrice`

```json
{ "disId": 56, "orderId": 200210, "price": "4.5" }
```

- 只改**实际价** `nx_do_price`，**期望价不变**
- 重算 `nx_do_price_different`、`nx_do_subtotal`
- **同步** GB 订单 `gb_do_price`、`gb_do_price_different`、`gb_do_subtotal`

### 4.6 取消出库

`POST api/platform/distributer/orders/cancelOutbound`

```json
{ "disId": 56, "orderId": 200210 }
```

- 订单 `purchase_status` 回退、`status` 回新单
- **同步** GB 订单 `gb_do_status=0`、`gb_do_buy_status=0`（与 `cancelOutOrder` 一致）
- fulfillment **`READY_FOR_PICKUP` → `ASSIGNED`**
- **不**走自有单的采购批次/库存扣减逻辑

### 4.7 出货中按商品聚合（仍与自有单合并）

平台单在「出货中」页仍与自有单按同一 SKU 聚合展示（只读）：

| 接口 | 用途 |
|------|------|
| `POST disGetTypePrepareOutPage` | 出货中商品分页 |
| `POST disGetTypePrepareOutDepCata` | 出货中客户 Tab |

**录重量/出库/改价/取消** 仍只用 §4.1 平台专用接口。

## 5. GB 饭店客户 — 出库接口（对比，勿混用）

GB 客户来自 `gbDisArrApp`，跳转 **`toDepOrdersGb` → `orderPageGb`**，使用 **GB 专用接口**：

| 步骤 | 接口 |
|------|------|
| 订单列表 | `POST api/nxdepartmentorders/phoneGetToFillDepOrdersGb` |
| 录入重量 | `POST api/nxdepartmentorders/updateOrderWeightGb` |
| GB 侧保存 | `POST api/gbdepartmentorders/chuKuDepSaveOrdersGb` 等 |

**平台客户不要走上述 GB 接口。**

## 6. 前端改造清单（jcJieDan）

1. **首页 `index.js`**
   - 保留 `disGetTodayOrderCustomer(disId)` → `nxDepArr`、`gbDisArrApp` 等。
   - **新增**请求 `POST api/platform/distributer/customers/today`，结果存 `platformCustomers`（或等价字段）。
   - **不要**再用 `deps.platformDep` 或 `buildCustomerGroups(platformDep, ownDep, nxDep)` 合并平台与自有客户。

2. **首页 `index.wxml`**
   - 独立区块渲染 `platformCustomers`（标题「平台客户」）。
   - `customerSections` / `nxDepArr` 只展示自有 nx 客户。
   - `gbDisArrApp` 区块 **不改**。

3. **点击平台客户 → orderPage**
   - 拉单：`POST api/platform/distributer/orders/lines`（**不要** `phoneGetToFillDepOrders`）
   - 出库：`finishOutbound`；暂存重量：`saveWeight`；改价：`updatePrice`；取消出库：`cancelOutbound`
   - 路由参数仍用 `routeDepFatherId` / `routeGbDepFatherId` 传给 lines 接口

4. **点击 GB 饭店**
   - 继续 `toDepOrdersGb`，**不要**改成平台或 nx 链路。

## 8. 联调示例

```bash
# 1. 平台客户列表
curl -X POST 'http://localhost:8080/nongxinle_war_exploded/api/platform/distributer/customers/today' \
  -H 'Content-Type: application/json' \
  -d '{"disId":56}'

  -d 'disId=56&depFatherId=-1&gbDepFatherId=57'

# 3b. 旧 NX 平台客户 / 自有 nx 客户
```
