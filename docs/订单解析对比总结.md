# 订单解析逻辑对比总结

## 对比文件

| 文件 | 用途 |
|------|------|
| `utils/pasteOrderParser.js` | Vue 项目，粘贴订单解析 |
| `lib/orderParser.js` | 微信小程序 paste 页面使用 |
| `paste.js` 的 `formatContent` | 调用 `lib/orderParser.js` 的 `parseOrderFromText` |

---

## 主要差异

### 1. 入口与预处理

| 项目 | lib/orderParser.js | utils/pasteOrderParser.js |
|------|-------------------|---------------------------|
| JSON 解析 | ✅ 优先尝试解析 JSON（AI 返回格式） | ❌ 无 |
| 兜底逻辑 | JSON 失败后用正则解析 | 直接正则解析 |

### 2. 返回值

| 项目 | lib/orderParser.js | utils/pasteOrderParser.js |
|------|-------------------|---------------------------|
| orders | ✅ | ✅ |
| formatted | ✅ | ✅ |
| invalidLineIndices | ❌ | ✅ 不合格行索引 |
| invalidSegments | ❌ | ✅ { lineIndex, segmentText } 用于精确高亮 |

### 3. 校验逻辑

| 项目 | lib/orderParser.js | utils/pasteOrderParser.js |
|------|-------------------|---------------------------|
| 解析后校验 | ❌ | ✅ 使用 validateOrder 校验每条订单 |
| 不合格片段收集 | ❌ | ✅ 收集 invalidSegments，支持片段级红色标注 |

### 4. 解析逻辑（正则、逗号、空格等）

- **核心逻辑基本一致**：`parseSegmentEndOfLine`、`parseLineWithSerial`、`parseLineWithComma`、`chineseNumberToArabic` 等实现相似
- `utils/pasteOrderParser.js` 中 parseLineWithComma 会为订单附加 `_sourceSegmentText`，用于后续精确匹配和高亮

---

## 结论与建议

1. **解析能力**：两者正则解析逻辑基本一致，差异主要在：
   - lib 多了 JSON 解析（需保留，用于 AI 输出）
   - pasteOrderParser 多了解析后校验和 invalidSegments 收集

2. **建议方案**：
   - 在 `lib/orderParser.js` 中补充：校验逻辑 + invalidSegments 收集
   - 或在 paste 页面直接使用 `utils/pasteOrderParser.js`，并在其入口增加 JSON 解析
   - 利用 invalidSegments 在复制文本中把不合格内容用红色标注
