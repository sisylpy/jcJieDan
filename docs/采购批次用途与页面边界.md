# 采购批次用途与页面边界

生效日期：2026-09-23。

Boss `purchaseBatchList / purchaseBatchDetail` 只展示真实 DPB。页面按服务端返回的权威用途区分：

- `CUSTOMER_ORDER`：客户订单订货。展示关联客户订单、供应方填报数量、单价、小计和供货进度；不展示或调用确认收货、部分收货、拒收、待入库。
- `INVENTORY_REPLENISHMENT`：库存备货。只有服务端返回真实库存记录时显示“查看库存记录”，缺少库存事实不得显示成“未收货”或“已生成库存”。
- `UNRESOLVED`：来源缺失或混合用途。继续在“全部”中显示并提示待核对，不由前端猜测归类。

供应方身份、采购用途和采购方式是不同维度。页面不得根据 `AUTO_SUPPLIER`、小程序来源、供应方名称或是否有 DPB 猜测用途。

客户订单外部供货商回复后，若服务端批次进度是 `BUYER_CONFIRM_REQUIRED`，Boss 详情只提供“前往精彩订货确认供货信息”，精确打开：

`pkgPurchase/pages/txs/disOrderBatch/disOrderBatch?batchId=...&fromBuyer=1&fromBoss=1`

实际确认由精彩订货 BUYER 完成，不在 Boss 复制表单。该事件确认供货数量、单价和小计并推进采购执行，不是收货、入库或付款。

库存备货状态为 `INVENTORY_RECEIPT_REQUIRED` 时，Boss 显示“前往精彩订货库存备货接收”，仍先经过上述安全批次页建立 BUYER 会话，再进入 `purchaseBatches` 中对应 `batchId` 的采购收货入口。库存备货不得调用客户订单的确认供货命令。

列表和详情只调用 `/api/owner/purchase-management/batches` 与 `/api/owner/purchase-management/batches/{id}`。不拼接 V1 查询、不回退旧供应商查询。日期从采购管理首页或用户选择继承；返回列表保留日期、用途、供应方、关键词、排序和滚动位置。
